# Оптимизация и алгоритмы

## O() notation
Нотация Big O (О-большое)Big O — это математический инструмент, который мы используем для оценки эффективности алгоритма по мере роста входных данных (\(n\)). 
Она показывает, как изменяются затраты времени (Time Complexity) или памяти (Space Complexity).
Во фронтенде это критично. Например, если у нас есть таблица или фильтр на 10 000 элементов, неэффективный алгоритм может намертво подвесить главный поток (Main Thread) и интерфейс «залипнет».

1. О(1) — Константное время (Constant)
Код выполняется за фиксированное время. Количество операций не зависит от размера входящих данных.

Что искать в коде: Прямой доступ, базовые математические операции, ветвления if/else (если внутри нет циклов).
```
const item = array[5];                 // Доступ по индексу
const value = obj['key'];              // Поиск в хэш-таблице / Map (в среднем)
const isEven = (num) => num % 2 === 0; // Математика
```

2. О(n) — Линейное время (Linear)
Код выполняет итерацию по всей коллекции от начала до конца. Количество операций растет строго пропорционально росту данных.

Что искать в коде: Одиночные циклы, итераторы, рекурсия с шагом -1.
```
// Обычный цикл
for (let i = 0; i < arr.length; i++) { ... }

// Встроенные методы массивов (под капотом у них циклы!)
arr.forEach(item => ...);
const filtered = arr.filter(item => ...);
const exactItem = arr.find(item => ...);
const hasElement = arr.includes(target);
```

3. О(n²) — Квадратичное время (Quadratic)
Количество операций растет как квадрат от размера данных. На массиве из 10 элементов это 100 операций, на 10 000 элементов — уже 100 000 000. В продакшене это главный кандидат на рефакторинг.

Что искать в коде: Вложенные циклы, где оба зависят от входных данных, или скрытые вложенные циклы (метод массива внутри другого цикла).
```
// Очевидный O(n^2): цикл в цикле
for (let i = 0; i < arr.length; i++) {
  for (let j = 0; j < arr.length; j++) { ... }
}

// Неочевидный O(n^2) (Ловушка на собеседованиях!):
// Метод includes() имеет сложность O(n) и вызывается внутри filter O(n)
const duplicates = arr.filter((item, index) => arr.indexOf(item) !== index);
```

4. O(log n) — Логарифмическое время (Logarithmic)
На каждом шаге алгоритма объем обрабатываемых данных уменьшается вдвое. Потрясающая скорость: для 1 000 000 элементов понадобится всего около 20 шагов.

Что искать в коде: Циклы, в которых итератор не увеличивается на 1 (i++), а умножается или делится на 2 (i = i * 2 или i = Math.floor(i / 2)).

Примеры: Бинарный поиск (работает только на отсортированных массивах), обход сбалансированных бинарных деревьев поиска.

```
let low = 0;
let high = arr.length - 1;
while (low <= high) {
  let mid = Math.floor((low + high) / 2); // Делим массив пополам на каждом шаге
  if (arr[mid] === target) return mid;
  if (arr[mid] < target) low = mid + 1;
  else high = mid - 1;
}
```

5. O(n log n) — Линейно-логарифмическое время
Обычно это результат комбинации: мы делим задачу пополам (как в логарифме), но на каждом уровне деления нам приходится сканировать весь массив (\(n\)).

Что искать в коде: Встроенная сортировка JS.
```
// Движок V8 (Chrome/Node.js) использует Timsort, его сложность в худшем/среднем — O(n log n)
const sorted = arr.sort((a, b) => a - b); 
```

## Memoization
Мемоизация — это конкретная техника оптимизации, разновидность кэширования. Суть проста: если функция чистая (при одинаковых аргументах всегда возвращает одинаковый результат), мы можем сохранить результат её выполнения. При повторном вызове с теми же аргументами мы не выполняем код заново, а сразу возвращаем значение из памяти за \(O(1)\).
Когда её применять во фронтенде?
* Тяжелые вычисления: Сложная фильтрация больших массивов, парсинг данных, графические расчеты.
* Предотвращение лишних рендеров: В компонентных фреймворках (React, Vue). Например, useMemo или React.memo предотвращают перерисовку компонентов или пересчет пропсов, если зависимости не изменились.

Простая реализация мемоизации на чистом JS:
Чтобы показать понимание под капотом, можно написать базовую функцию-обертку (HOC / декоратор)
```
function memoize(fn) {
  // Используем Map для хранения кэша (ключ -> результат)
  const cache = new Map();

  return function (...args) {
    // В реальном проекте нужен более сложный сериализатор ключей для объектов
    const key = JSON.stringify(args); 

    if (cache.has(key)) {
      console.log('Взято из кэша для аргументов:', args);
      return cache.get(key);
    }

    const result = fn(...args);
    cache.set(key, result);
    return result;
  };
}

// Пример использования (Тяжелая функция)
const heavyCalculation = (num) => {
  console.log('Выполняем долгий расчет...');
  return num * 2; // Представим, что тут сложный алгоритм
};

const memoizedCalc = memoize(heavyCalculation);

memoizedCalc(10); // Выведет: "Выполняем долгий расчет..." -> 20
memoizedCalc(10); // Выведет: "Взято из кэша..." -> 20 (мгновенно)
```
Важные подводные камни мемоизации (О чем стоит упомянуть):
* Потребление памяти (Trade-off): Мы меняем процессорное время (Time) на оперативную память (Space). Если кэшировать всё подряд или кэшировать функции с огромным количеством уникальных аргументов, можно вызвать утечку памяти или переполнение. В production-решениях (например, из библиотеки Lodash) часто используют ограничение размера кэша (LRU-кэш — Least Recently Used).
* Сравнение по ссылке: В JS объекты и массивы сравниваются по ссылке, а не по значению. Если аргумент — объект, JSON.stringify может быть медленным (\(O(n)\)), что убьет всю выгоду от мемоизации.
## Как применяют это на практике?
Обычно оптимизация во фронтенде строится на стыке этих понятий. 
Например, если мне нужно сопоставить данные из двух массивов: users (1000 элементов) и orders (10 000 элементов).
* Плохой подход \(O(n \cdot m)\): Запустить цикл внутри цикла (orders.map(order => users.find(...))). На каждой итерации искать юзера перебором.
* Сеньор-подход \(O(n + m)\): Сначала за один проход (\(O(n)\)) превратить массив юзеров в Map (хэш-таблицу), где ключ — id. А затем пройтись по заказам (\(O(m)\)) и брать юзера из Map за константное время \(O(1)\).
